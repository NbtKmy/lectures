Task 3 from scratch

From one hospital to 41: how many of Moriyama Ward's residents can walk to a hospital in 10, 20 or 30 minutes.

In the session you saw one result: the share of Moriyama Ward's residents who can walk to at least one hospital in 10, 20 or 30 minutes. Here is how to get it yourself. It reuses what you built for one hospital in Task 2 from scratch and adds only what is new: all hospitals at once, a different way of drawing the reach, and the count over the whole ward.

The heavy lifting is done by four short Python scripts that you run in the QGIS Python console. They are in the repository. You do not have to write any code. Menu names follow QGIS 3.44.

Same ballpark, not the same digits. The roads come from OpenStreetMap, which changes daily. Your percentages will be close to 17.90%, 46.61% and 62.60%, not identical.

Step 1 · What you need from Task 2

Do steps 0 to 4 of the Task 2 page. You do not need steps 5 to 8: those are the one-hospital test.

  • the ward boundary (moriyama_admin_field) and the 3 km buffer (moriyama_buffer_3km)
  • the population grid moriyama_mesh_3km, with its population field
  • the walkable roads moriyama_osm_walkable_preliminary
  • the project saved as moriyama.qgz (the scripts write to a folder access_results/ next to it)

The scripts find layers by name. In the Layers panel, select a layer and press F2 to rename it. Rename the ward boundary from moriyama_admin_field to moriyama_boundary. The four names must be exactly:

Layer nameWhat it is
moriyama_boundaryward outline, one polygon
moriyama_mesh_3kmpopulation grid with population
moriyama_osm_walkable_preliminarywalkable roads
moriyama_buffer_hospitalsthe hospitals (made in step 2)

All four must be in EPSG:6675.

Step 2 · All hospitals in and around the ward

In Task 2 you picked one hospital. Now take every hospital within 3 km of the ward, so that residents near the border are counted with the hospitals just across it.

  1. If P04-20_23.geojson is not in the project, drag it in (see Task 2, step 5).
  2. Extract by expression: "P04_001" = 1 (class 1 = hospital; clinics and dental clinics are left out).
  3. Extract by location on the result. Predicate: intersect. Compare against: moriyama_buffer_3km.
  4. Reproject layer to EPSG:6675. Save as moriyama_buffer_hospitals.gpkg and add it to the project.

Checkpoint. 41 points (the repository file moriyama_buffer_hospitals.gpkg has 41). Eight of them stand inside the ward; Kawashima Hospital is one of the eight.

Step 3 · The reach of every hospital: run the scripts

Task 2 drew the reach with a smoothed surface. Doing that 41 times, three times each, is too much by hand, and the polygon routine needs a plugin that does not run on every machine. So Task 3 uses a simpler way to turn roads into an area: take all roads reachable within the time, and put a 30 m buffer around them. That makes it an approximation (see the note at the end), and it is also why the Task 2 and Task 3 numbers must not be compared.

How to run a script

  1. Plugins ▸ Python Console (Ctrl/⌘+Alt+P).
  2. Click Show Editor, then Open Script…, and choose the .py file.
  3. Click Run Script (the green triangle). Read the messages in the console below.

Download the scripts from the repository (click a name, then Download raw file). The messages they print are in Japanese; I translate the important ones.

3a · Thirty minutes

find_roads_to_hospitals.py runs Service area (from layer) for all 41 hospitals at once: shortest path, both directions, 2000 m (4 km/h × 30 min). It needs the layers moriyama_buffer_hospitals and moriyama_osm_walkable_preliminary, and stops if their CRS is not EPSG:6675.

Checkpoint. The console prints 病院数 (hospitals): 41 and 到達道路の地物数 (reachable-road features): 41, one feature per hospital. 道路へ接続できなかった病院 (hospitals that could not be attached to the road network): 0. A layer moriyama_all_hospitals_30min_lines appears.

That layer is temporary (a small chip next to its name in the Layers panel). Keep QGIS open until step 4 is done, or export it: right-click ▸ Export ▸ Save Features As… ▸ GeoPackage, and add the saved file with the same layer name.

3b · Ten and twenty minutes

create_roads_to_hospitals_10and20min.py does the same for 666.67 m and 1333.33 m and saves them as GeoPackages in access_results/ next to your project. If a file is already there, it skips that time and says so; delete the file to run it again.

Checkpoint. Two new layers, moriyama_hospitals_10min_lines and moriyama_hospitals_20min_lines, with 41 features each.

These are cumulative reaches: "within 10 minutes", "within 20 minutes", "within 30 minutes". The 30-minute reach contains the 20-minute one, which contains the 10-minute one. They are not bands.

Step 4 · From roads to areas

line_to_30mbuffer_polygon.py takes the three line layers and runs Buffer (30 m) on each, without dissolving, so every hospital keeps its own shape. It writes moriyama_hospitals_10min_buffer30m.gpkg, …20min… and …30min….

Checkpoint. Three polygon layers with 41 features each. Switch them on one after another: each should be wider than the last.

Optional but quick: check that the three layers contain the same 41 hospitals. In the Python console, paste:

from qgis.core import QgsProject
p = QgsProject.instance()
names = {m: f'moriyama_hospitals_{m}min_buffer30m' for m in (10, 20, 30)}
d = {}
for m, n in names.items():
    rows = [(f['fid'], f['P04_002']) for f in p.mapLayersByName(n)[0].getFeatures()]
    assert len(rows) == len(set(k for k, v in rows)) == 41
    d[m] = dict(rows)
assert d[10] == d[20] == d[30]
print('41 hospitals x 3 reaches: same IDs and names')

Step 5 · Count the residents

analysis_B.py answers the question of this task. For each of the three times it:

  1. Fixes any broken geometry in the 41 buffers.
  2. Dissolves the 41 buffers into one shape: the area within reach of at least one hospital. A resident near two hospitals is therefore counted once.
  3. Clips that shape to moriyama_boundary, so only the ward's residents are counted.
  4. Applies area apportioning on the population grid twice: for the whole ward (the denominator) and for the clipped reach (the numerator). The share is numerator ÷ denominator × 100.

Cells whose population is NULL are left out of both counts, not set to 0. The script writes moriyama_analysis_B_accessibility.csv and three coverage layers into access_results/. It refuses to overwrite earlier results: delete those four files before you run it again.

Checkpoint. The numbers in the session were:

Walking timeResidents within reachShare
10 min31,287.8017.90%
20 min81,492.4146.61%
30 min109,452.9362.60%

The whole ward: 174,833.87 estimated residents, with 96 grid cells that have no population value. Your figures should be close. In any case they must rise from 10 to 30 minutes and stay between 0% and 100%; the script warns you if not. Repository files: moriyama_analysis_B_accessibility.csv and moriyama_analysis_B_{10,20,30}min_coverage.gpkg.

If something stops

  • "レイヤが見つかりません" / "レイヤがありません" (layer not found): a layer name differs from the table in step 1.
  • "CRSが異なります" (different CRS): re-export that layer in EPSG:6675.
  • "…が41地物ではありません" (not 41 features): step 2 gave a different number of hospitals than the script expects. Count them; if your count is right, change the 41 in the script.
  • "FileExistsError": delete the output files named in the message.

Approximate, potential access. The reach is "roads within walking distance, plus 30 m". That is not a true walking-time area, and a different buffer width would change the answer. The result shows who could walk to a hospital, not who does, and says nothing about what the hospital offers. See Limits.

Per-hospital counts (analysis A). The repository also has analysis_A.py, which counts the residents around each of the eight hospitals in the ward separately. It is not part of this task. It holds a fixed list of hospital IDs (fid) from the author's layer. Your fid values depend on how you exported the file, so check and change that list before running it.
