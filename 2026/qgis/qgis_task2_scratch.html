Task 2 from scratch

From the public downloads to one number: how many people live within a 10-minute walk of Kawashima Hospital.

In the session you opened a finished project and clicked through it. Here you build it yourself, from the public downloads to the number: how many people live within a 10-minute walk of Kawashima Hospital (川島病院), Moriyama Ward, Nagoya. The answer in the session was about 5,421.

It is the long way round. Most steps are short; the downloads and the road query take the time. You can jump in at any checkpoint: each one names the file in the repository that you can load instead of making it yourself. Menu names follow QGIS 3.44.

Same ballpark, not the same digits. OpenStreetMap changes every day, so the road network you download will not be the one used in the session. Expect a result close to 5,421, not exactly 5,421. The population grid and the hospital are fixed, so only the roads move the number.

Step 0 · Set up

  1. Make a folder, for example moriyama/. Start a new QGIS project and save it there as moriyama.qgz. (Task 3 needs the saved project, because its scripts write next to it.)
  2. Click the CRS button at the bottom right of the QGIS window. Search for 6675 and choose JGD2011 / Japan Plane Rectangular CS VII. This is a projected system in metres, made for Aichi.
  3. Install two plugins: Plugins ▸ Manage and Install Plugins…, search for QuickOSM and QNEAT3.

One rule for the whole page. Every layer you save gets CRS EPSG:6675. The walking distance and the buffer below are measured in the units of the layer. In a latitude/longitude system those units are degrees, and 666.67 degrees is nonsense. To save a layer: right-click ▸ Export ▸ Save Features As…, format GeoPackage, set the CRS, set the file name.

Step 1 · The ward boundary

You already have the boundaries from Task 1: aichi_admin_fields2025.geojson (MLIT N03, 2025). Moriyama Ward is the polygon with municipality code 23113.

  1. Drag aichi_admin_fields2025.geojson into QGIS.
  2. Open the Processing Toolbox (Ctrl/⌘+Alt+T) and run Extract by expression. Expression: "N03_007" = '23113'. Run.
  3. Run Reproject layer on the result. Target CRS: EPSG:6675. Save the output as moriyama_admin_field.gpkg.

Checkpoint. One polygon, ward name 守山区. Repository file: moriyama_admin_field.gpkg.

Step 2 · A 3 km buffer around the ward

The population grid, the roads and (in Task 3) the hospitals are all cut with this buffer, not with the ward itself. People walk across ward borders, so the working area must reach past it.

  1. Run Buffer. Input: moriyama_admin_field. Distance: 3000 (metres). Save as moriyama_buffer_3km.gpkg.

Checkpoint. One polygon, a bit more than 3 km wider than the ward on every side.

Step 3 · The population grid

The 2020 Census publishes population on a grid of about 250 m cells. You need two downloads from e-Stat (統計地理情報システム): the boundaries of the cells, and a table with one population value per cell. The two meet on the cell code KEY_CODE.

e-Stat changes its menus now and then. The file names below are the reliable anchors.

3a · Cell boundaries

  1. Go to 境界データダウンロード. Choose the 2020 Census (令和２年国勢調査), the 250 m mesh (5次メッシュ), Shapefile.
  2. Download two sheets: MESH05236 and MESH05237. Moriyama Ward lies across both.
  3. Unzip them. Keep the .shp, .shx, .dbf and .prj files of each together in one folder.
  4. Drag both .shp files into QGIS.
  5. Run Merge vector layers on the two. Destination CRS: EPSG:6675. Save as mesh_merged.gpkg. (It is large: about 200,000 cells.)
  6. Run Extract by location. Input: mesh_merged. Predicate: intersect. Compare against: moriyama_buffer_3km. Save as mesh_local.gpkg.

Cut first, join second. The first time we did this, the table was joined to all 200,000 cells and then filtered. QGIS stopped responding. Cutting down to the local cells first keeps everything light.

3b · Population table

  1. Go to 統計データダウンロード. Choose the 2020 Census, the 250 m mesh, Aichi (愛知県). The file you need is the one named tblT001142Q23. It holds, among other things, the total population of each cell.
  2. Add it with Layer ▸ Add Layer ▸ Add Delimited Text Layer…. File format: CSV. Encoding: Shift_JIS (also listed as CP932). Geometry definition: No geometry (attribute only table).
  3. Open its attribute table. Row 1 is a line of Japanese column descriptions, not a cell. It will simply find no partner in the next step. Because of this row, QGIS reads every column as text. You fix that in step 3d.

3c · Join and save

  1. Double-click mesh_local ▸ Joins ▸ green +. Join layer: the CSV. Join field: KEY_CODE. Target field: KEY_CODE. Keep the default prefix (tblT001142Q23_): the expression in step 3d uses it.
  2. A join is only virtual. Make it real: right-click mesh_local ▸ Export ▸ Save Features As… ▸ GeoPackage, CRS EPSG:6675, file moriyama_mesh_3km.gpkg. Add it to the project.

3d · Text to number

  1. Open the Field Calculator on moriyama_mesh_3km. Create a new field population, type Whole number (integer), expression: 
    to_int("tblT001142Q23_T001142001")
  2. Save the edits (the pencil button, then the save button).

Empty is not zero. Some cells have no population value in the table. They stay NULL. Do not turn them into 0: nobody knows from this table whether they are empty land or hidden by the statistics office. See Limits.

Checkpoint. moriyama_mesh_3km has 2,745 cells. Select by expression "population" IS NULL: 308 cells are selected. Repository file: moriyama_mesh_3km.gpkg.

Step 4 · Walkable roads

4a · Download the roads

  1. Plugins ▸ QuickOSM ▸ QuickOSM. On the Quick Query tab, Key: highway, Value: leave empty (every road, path and footway).
  2. Query area: Layer Extent, layer moriyama_buffer_3km. This uses the rectangle around the buffer, which is a little larger than the buffer itself. That is fine, and it keeps routes at the edge from being cut off.
  3. Run. QuickOSM returns three layers: points, lines, polygons. Keep only the lines; they are the network. (The points are things like traffic lights, and the polygons are road areas.)
  4. Save the lines layer as moriyama_osm_highway_line.gpkg with CRS EPSG:6675. QuickOSM delivers latitude/longitude, so this export is the reprojection.

4b · Keep what a pedestrian can use

  1. Run Extract by expression on moriyama_osm_highway_line with this expression, and save as moriyama_osm_walkable_preliminary.gpkg: 
    "highway" IN (
    'residential', 'living_street', 'unclassified',
    'tertiary', 'tertiary_link',
    'secondary', 'secondary_link',
    'primary', 'primary_link',
    'service', 'footway', 'pedestrian', 'path', 'steps'
)
AND (
    "foot" IS NULL OR "foot" NOT IN ('no', 'private')
)
AND (
    "access" IS NULL
    OR "access" NOT IN ('no', 'private')
    OR "foot" IN ('yes', 'designated', 'permissive')
)

In words: ordinary streets, footways and steps; but not where OpenStreetMap says foot=no or private. Motorways and cycle-only paths are left out on purpose.

A first cut, not a verdict. This rule ignores opening hours, missing pavements, and lines that cross without joining (a bridge over a road, an underpass). Whether the network is connected is something you would check in real research.

Checkpoint. About 50,000 lines, from about 52,000 before the filter. (The session run had 50,075 of 52,200; yours will differ a little. See the note at the top.)

Step 5 · The hospital

Hospital locations come from MLIT's Medical Institutions data (P04), 2020 edition, CC BY 4.0. Download the Aichi file (P04-20_23; the GeoJSON version is easiest) and unzip it. The field P04_001 is the class of facility: 1 hospital, 2 clinic, 3 dental clinic. P04_002 is the name.

  1. Drag P04-20_23.geojson into QGIS.
  2. Run Extract by expression: 
    "P04_001" = 1 AND "P04_002" LIKE '%川島病院%'
  3. Run Reproject layer to EPSG:6675. Save as moriyama_hospital_test.gpkg.

Checkpoint. One point: 医療法人和光会 川島病院, address 名古屋市守山区白山3-501. Repository file: moriyama_hospital_test.gpkg.

Step 6 · How far can you walk? As lines

Walking speed is set to 4 km/h. Ten minutes is then 4000 m × 10/60 h = 666.67 m of walking along the roads.

  1. In the Processing Toolbox run Service area (from layer) (under Network analysis) with:
    • Vector layer representing network: moriyama_osm_walkable_preliminary
    • Path type to calculate: Shortest
    • Vector layer with start points: moriyama_hospital_test
    • Travel cost: 666.67 (metres, because the path type is Shortest)
    • Direction field: empty. Default direction: Both directions. Topology tolerance: 0
    • Service area (boundary nodes): skip the output. Service area (lines): save as moriyama_service_area_lines.gpkg

Checkpoint. One feature: all the roads reachable on foot in 10 minutes, as a web of lines around the hospital. Repository file: moriyama_service_area_lines.gpkg. This is already an answer in the form of lines; the next step turns it into an area so we can count people inside it.

Step 7 · The same reach, as an area

QNEAT3 interpolates a walking-distance surface over the road network. You then cut that surface at 666.67 m.

  1. In the Processing Toolbox, under QNEAT3, run Iso-Area as Polygons (from Layer):
    • Network Layer: moriyama_osm_walkable_preliminary; Start Points: moriyama_hospital_test; Unique Point ID Field: fid
    • Size of Iso-Area: 666.67; Contour Interval: 666.67; Cell size: 10 (metres)
    • Strategy: Shortest; Default direction: Both; Topology tolerance: 0
  2. You get Output Interpolation (a raster) and Output Polygon. Use the raster. Check it: Properties ▸ Information shows CRS EPSG:6675, cells of about 10 m, NoData -9999, and values from about 18 up to about 731.
  3. Raster ▸ Raster Calculator. Expression (use the layer name as QGIS shows it): 
    ("Output Interpolation@1" >= 0)
AND ("Output Interpolation@1" <= 666.67)
    Output layer: moriyama_10min_mask.tif; output extent and CRS from the Interpolation layer. Cells inside the reach become 1, other cells 0.
  4. Processing Toolbox ▸ Polygonize (raster to vector). Input: the mask, band 1, field name DN. Save as moriyama_10min_polygon_raw.gpkg.
  5. Keep only the inside. Run Extract by expression on the raw polygons: "DN" = 1. Save as moriyama_10min_polygon_clean.gpkg.

Never skip the last step. Polygonize also draws the outside cells (DN = 0) as polygons. In the first run of this analysis those slipped into the count: the answer was about 6,878 instead of 5,421, some 1,457 people too many. The tell-tale was an outline that looked doubled on the map. The geometry was valid; the selection was wrong.

Why not the polygon QNEAT3 offers? It is drawn by a different routine, which on the author's Mac stopped with ModuleNotFoundError: No module named 'contourpy' (a Python package that then also failed macOS's code-signing check). Going through the raster avoids that, and it is the route whose numbers are reported in the session. Its shape is not identical to the polygon output, so do not mix them. The plugin has since been rebuilt as QNEAT 4, where this tool is called Iso-area from layer; these steps were not tested with it.

Checkpoint. The clean polygon is one feature. Draw it under the service-area lines: the lines should sit inside it, apart from a few places at the edge where the interpolation is only approximate. Repository file: moriyama_test_10min_polygon_clean.gpkg.

Step 8 · Count the people

A grid cell half inside the reach gets half its people. This is area apportioning, and it assumes people are spread evenly in a cell.

  1. Open the Field Calculator on moriyama_mesh_3km. New field mesh_area_m2, type Decimal number (real), expression area($geometry). Do this before the intersection: you need each cell's full area.
  2. Run Intersection. Input layer: moriyama_mesh_3km. Overlay layer: moriyama_10min_polygon_clean. Save as moriyama_10min_intersection.gpkg. Every cell that touches the reach is now cut to the reach's edge.
  3. Field Calculator on the intersection. New field pop_est, type Decimal number (real): 
    "population" * area($geometry) / "mesh_area_m2"
    The piece's area divided by the full cell's area, times the cell's population. Use area($geometry) in both places so the two areas are measured the same way.
  4. In the Processing Toolbox, type Basic statistics into the search field and double-click Basic statistics for fields (under Vector analysis). Input layer: the intersection. Field to calculate statistics on: pop_est. Click Run and read SUM in the Log tab.

Checkpoint. 20 pieces, Sum close to 5,420.9 in the session run, so about 5,421 people. A few percent either way is to be expected with today's roads. Repository file: moriyama_test_10min_intersection_with_population_clean.gpkg (20 pieces).

What to write down

The number is only meaningful with its conditions. Keep a note of: the date of the OpenStreetMap download, the road filter above, walking speed 4 km/h, 666.67 m, the CRS, the cell size 10 m, the DN = 1 filter, the area formula, and your QGIS version.
